# Kaggle and Arena portal comparison

Reviewed 12 September 2026 against Arena's current code and Kaggle's official documentation. Arena supports the core local learning and evaluation loop, but does not yet provide full Kaggle parity.

## Workflow comparison

| Area                     | Kaggle workflow                                                                 | Arena status and remaining work                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Discovery and navigation | Browse resources, then open their detail pages and related work.                | Competitions, code, discussions and benchmark collections already have page routes. This update adds dataset/model pages with direct links, file details, previews where supported, and notebook creation. Courses and lessons have their own routes (`#courses/<id>`, `#courses/<id>/lessons/<lessonId>`); legacy CSV benchmark details still use older views.                                                                                                                     |
| Personal workspace       | Your Work brings created/shared resources and activity together.                | Owner management supports datasets, models, notebooks, competitions and benchmarks. This update preserves the selected category in the URL, including the benchmark landing page shortcut. A unified shared-with-me, bookmarks, activity and collections workspace remains incomplete.                                                                                                          |
| Datasets and reuse       | Start a notebook from a dataset or attach it from the editor.                   | Datasets have immutable numbered versions with notes and carry-over, a version history, a multi-file browser with bounded previews (tables with column summaries, JSON, text, images, NumPy, ZIP listings), resumable chunked uploads of any size and per-user storage quotas ([datasets](datasets.md)). Notebooks pin a version or follow the latest, including in background and scheduled runs. Parquet previews (no pyarrow offline), dataset collaborators with write access and data APIs remain gaps. |

## Changes in this update

- `#datasets/<id>` and `#models/<id>` open full detail pages from discovery and Your Work. Browser refresh and direct links retain the resource.
- **New notebook** creates a private temporary draft with the selected resource. File references are pinned when the draft is created, permission-checked again when opened, then materialized under its workspace `input/<source-folder>/` directory.
- Saving preserves the input metadata with the notebook. Discarding removes the temporary draft and its context; it does not delete the original dataset or model.
- A new additive `notebook_draft_inputs` table stores draft source context. Existing competition context and join requirements remain in place.
- Your Work categories use `#work/datasets`, `#work/models`, `#work/notebooks`, `#work/competitions` and `#work/benchmarks`; `#work` shows all work. Reload and browser history restore the category.

## Recommended implementation order

1. Done: general notebook runs store executed versions without competition scoring ([compute](compute.md)).
2. Unify resource visibility, sharing and ownership across datasets, model artifacts and notebook outputs, including private models and consistent group access.
3. Done: resumable chunked transfers, large model weights, paginated file lists, bounded previews and storage quotas ([datasets](datasets.md)). Object storage, folder-tree navigation and verified restore procedures remain.
4. Extend Your Work with shared resources/bookmarks and add organizer/moderation tools with audit history.

These are further implementation tasks, not features completed by this portal update. Learning (authoring, graded exercises, certificates) is described in [learn](learn.md).

## Validation

The API regression suite passed 146 tests, including resource draft creation, immutable input selection, save/discard behavior and private dataset access. The web production build passed. Browser checks cover dataset/model detail routes, refresh and Back navigation, category-specific Your Work links, mobile overflow, first model-file upload, and automatic dataset attachment in a real notebook session.
